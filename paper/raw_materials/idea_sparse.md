# Project Technical Specification (`idea_sparse.md`)

## 1. Core Thesis & Scope
`mini-inference-stack` is an empirical, profile-guided systems study of LLM inference optimization on a single consumer NVIDIA Blackwell laptop GPU (`RTX 5080 Laptop`, `sm_120`). Rather than proposing a novel production serving framework to replace vLLM, the project takes an honest empirical and educational systems approach: measure a baseline, attribute bottlenecks across host and device using hardware profilers (`nsys`, `ncu`), apply one architectural optimization at a time, verify strict greedy token parity, and quantify both end-to-end throughput/latency shifts and kernel-level roofline movement.

## 2. Hardware & Software Environment
All 10 evaluated stages share an identical hardware and software stack (single-node, single-GPU, fixed `config.yaml`):
- **GPU:** NVIDIA GeForce RTX 5080 Laptop GPU, 16 GB GDDR7, Blackwell architecture (`sm_120`).
- **Roofline Ceilings (`config.yaml`):** Physical peak DRAM bandwidth `896.0 GB/s`; BF16 Tensor Core compute ceiling `40.0 TFLOP/s` (note: NCU sustained-clock DRAM utilization % is reported relative to sustained laptop clocks alongside physical-ceiling %; tensor FLOPs are estimated as `inst × 4096`).
- **OS & Runtime:** Windows 11 + WSL2 (Ubuntu 24.04 LTS), CUDA 13.1 (`nvcc 13.1.80`), Python 3.12 (`uv`), PyTorch `2.13.0+cu130`, Triton `3.7.1`, vLLM `0.31.0`.
- **Target Model:** `Qwen/Qwen2.5-Coder-1.5B-Instruct` (`bfloat16`, ~1.54B params / `2.907 GB` weights, 28 Transformer layers, 12 Q heads, 2 KV heads [6:1 GQA], `head_dim = 128`, `hidden_size = 1536`, `rope_theta = 1,000,000.0`, tied `lm_head`, `max_model_len = 9216`).
- **Draft Model (vLLM Stage 1 only):** `Qwen/Qwen2.5-Coder-0.5B-Instruct` (`bfloat16`, ~0.49B params, `num_speculative_tokens K = 5`).
- **Profilers:** NVIDIA Nsight Systems (`nsys`) for CPU/CUDA API/GPU timeline attribution and NVIDIA Nsight Compute (`ncu`) for standalone Layer 0 kernel roofline and hardware-counter analysis.

## 3. Dual-Track Experimental Methodology
The codebase is split into two parallel tracks with distinct experimental philosophies:

### Track A: `vllm-reference/` (Feature Isolation)
Uses production vLLM `0.31.0`—which already includes FlashAttention, PagedAttention, continuous batching, fused kernels, and CUDA graphs in its baseline—to establish upper-bound targets and isolate high-level serving features one at a time (each branched directly from Stage 0 to avoid profiling cross-pollution):
1. **`stage-0-vllm` (`vllm-reference/stage-0-baseline/`):** Frozen reference baseline (`bfloat16`, `gpu_memory_utilization = 0.70`, prefix caching off).
2. **`stage-1-vllm` (`vllm-reference/stage-1-spec-dec/`):** Draft-model speculative decoding (`Qwen2.5-Coder-0.5B-Instruct`, $K=5$). Evaluates the GEMV→GEMM arithmetic intensity shift vs. draft-to-target size ratio, host launch overhead, and concurrency crossover.
3. **`stage-2-vllm` (`vllm-reference/stage-2-prefix-cache/`):** Automatic Prefix Caching / RadixAttention (`--enable-prefix-caching`). Evaluates shared-prefix KV reuse, prefill compute elimination, and multi-tenant queuing collapse.

### Track B: `custom-serving/` (Strictly Additive, Stages 0 → 6)
Reconstructs a modern LLM serving engine from first principles in Python/PyTorch/Triton. Each stage `N` copies stage `N-1` and adds **exactly one** architectural upgrade, exposing how solving one bottleneck immediately shifts execution to the next:
1. **`stage-0-custom` (`stage-0-baseline/`):** Naive eager PyTorch (`.safetensors` loader, explicit `(Q @ K^T)` attention with `repeat_interleave`, no SDPA, no KV cache, full-sequence $O(S^2)$ decode recomputation, global `asyncio.Lock` serialization, single-thread `ThreadPoolExecutor(max_workers=1)` for CUDA thread affinity).
2. **`stage-1-custom` (`stage-1-kv-cache/`):** Per-layer unexpanded `(K, V)` cache (`[B, 2, S, 128]`), offset RoPE, single-token `[1, 1]` decode without causal mask. Collapses decode from $O(S^2)$ to $O(S)$ but retains eager PyTorch attention and `torch.cat` KV reallocation.
3. **`stage-2-custom` (`stage-2-tiled-attn/`):** Custom Triton FlashAttention-2 forward kernel (`_flash_attention_fwd`) with SRAM online fp32 softmax (`BLOCK_M=64` prefill / `BLOCK_M=16` decode, `BLOCK_N=64`), native GQA indexing (`kv_head_idx = head_idx // 6`), analytical causal masking, and zero-copy output layout. Eliminates $O(S^2)$ HBM attention matrix materialization.
4. **`stage-3-custom` (`stage-3-split-k/`):** Two-stage Triton Split-K / FlashDecode decode pipeline (`_flash_attention_decode_splitk_fwd` + `_flash_attention_splitk_combine`, up to `MAX_SPLITK_SPLITS=32`) for $q_{\text{len}}=1$, partitioning `L_kv` across parallel CTAs without `BLOCK_M=16` padding waste while retaining `_flash_attention_fwd` for prefill.
5. **`stage-4-custom` (`stage-4-paged-kv/`):** Physical KV block pool (`BlockAllocator`, `KV_BLOCK_SIZE = 16`, `num_blocks = 4096`), Triton `_reshape_and_cache` in-place scatter, indirect `block_table` gather in attention kernels, and a lock-free iteration-level continuous batching scheduler (`PagedEngine.run_scheduler_loop`, `max_batch_size = 64`, equal-length prefill grouping, batched $M=B$ decode, single batch `.tolist()` sampling D2H, recomputation preemption).
6. **`stage-5-custom` (`stage-5-fused-ops/`):** Three custom Triton fused operators + combined MLP weights: (i) `_rms_norm_fwd` with fp32 variance and threaded residual-add fusion (`HAS_RESIDUAL=True`), (ii) in-place 4D-strided `_rope_embedding_fwd` eliminating `rotate_half` slicing and all `CatArrayBatchedCopy` launches, and (iii) merged `gate_up_proj` linear layer + 2D-tiled `_swiglu_fwd`.
7. **`stage-6-custom` (`stage-6-cuda-graphs/`):** Bucketed `DecodeGraphRunner` capturing fixed-shape decode (`q_len == 1`) into static `torch.cuda.CUDAGraph` buckets $B \in \{1, 2, 4, 8, 16, 32, 64\}$ with capture-safe zero-sync forward (`max_context_len` static `int`) and padded-lane KV/RoPE/attention masking (`context_lengths[pad] == 0`), keeping variable-length prefill eager.

## 4. Serving Contract, Parity & Evaluation Protocol
- **Serving Contract:** Every engine exposes an OpenAI-compatible streaming `POST /v1/chat/completions` SSE endpoint on `127.0.0.1:8000`, serves `Qwen/Qwen2.5-Coder-1.5B-Instruct`, honours `ignore_eos`, and emits a final `usage` chunk.
- **Correctness Verification (`custom-serving/test_parity.py`):** Every custom stage is validated against HuggingFace `AutoModelForCausalLM` (`eager` for Stages 0–1; `sdpa` for Stages 2–6) for single-step prefill logit tolerance (`0.062500` eager / `0.218750` sdpa) and `32/32` (100%) greedy token ID parity (`temperature = 0.0`), plus batched (`B=4`), padded-lane (`B=3 -> bucket B=4`), and KV block reclamation (`256/256` free blocks) checks for Stages 4–6. All recorded benchmark JSON sweeps completed with `failed = 0`.
- **Closed-Loop Benchmark Protocol (`benchmarks/bench_closed_loop.sh` via `vllm bench serve`):**
  - *Concurrency (Pareto) Sweep:* Fixed Python code prompt adjusted to `512` input tokens, `128` output tokens, greedy (`temperature = 0.0`, `seed = 42`), concurrencies $C \in \{1, 2, 4, 8, 16, 32, 64\}$ (serialized Stages 0–3 capped at $C \le 16$). Tracks `output_throughput`, `mean_tpot_ms`, `p50_itl_ms`, `p90_itl_ms`, `p99_itl_ms`, `mean_ttft_ms`, `p99_ttft_ms`.
  - *Context-Length Sweep:* Single-stream $C = 1$, $L \in \{128, 256, 512, 1024, 2048, 4096, 8192\}$ input tokens, `64` output tokens, `num_prompts = 10` (Stages 0–3 capped at $L \le 2048$). Tracks `mean_ttft_ms`, `mean_tpot_ms`, `output_throughput`.
- **Profiling Protocol:**
  - *Nsight Systems (`profile_nsys.sh`):* Captures live server execution (`NSYS=ON serve.sh`, excluding startup) for $C=1$, `1024` input / `64` output tokens. Extracts wall time, kernel count, GPU active/idle union intervals, `cpu_launch_calls`, `cpu_launch_overhead_ms`, `cuda_graph_launches`, `decode_step_avg_ms`, and operator category breakdown (NVTX ranges for custom stages; GPU kernel timeline split for vLLM).
  - *Nsight Compute (`profile_ncu.sh`):* Standalone Layer 0 profiler (server stopped to avoid VRAM contention) measuring Prefill ($L=2048$) and Decode ($M=1$; or $M=K+1=6$ verification for `stage-1-vllm`) kernel duration, DRAM throughput, attained TFLOP/s, arithmetic intensity, occupancy, and register spills. Stage 0 custom deferred NCU because `nsys` already conclusively isolated $O(S^2)$ decode recomputation.
