# AGENTS.md

Educational LLM-inference lab: vLLM reference vs. from-scratch engines, benchmarked + profiled on one RTX 5080 laptop GPU.
Read `README.md` (overview, layout) and `WORKFLOW.md` (commands, procedure) first. This file holds only what they don't say.

## Don't touch
- `benchmarks/results/<stage>/*.json` of recorded stages — measurements, regenerate only by re-running scripts.
- `benchmarks/results/dashboard.html` — generated by `plot_dashboard.py`; pushing it to `main` deploys GitHub Pages.
- `vllm-reference/stage-0-baseline/` — frozen baseline. New idea → new stage dir.
- `model.*` and `benchmarks.*` in `config.yaml` — changing them invalidates cross-stage comparisons.
- **Never plain `uv sync`.** `vllm` 0.31.0 and `torch` 2.13.0+cu130 were installed with `uv pip`, not declared in
  `pyproject.toml`; exact sync deletes them. Use `uv sync --inexact` / `uv add --no-sync`. `uv run` is safe.

## Contracts between parts
- `config.yaml` is parsed independently (inline Python heredoc + `eval`) by `serve.sh`, every `benchmarks/*.sh`,
  and `ui/app.py`. Renaming a key breaks readers silently or with `KeyError`. Precedence: env var > config > script default.
- Stage name (`stage-<N>-<track>`, e.g. `stage-0-vllm`) is the join key for `benchmarks/results/<stage>/`,
  `benchmarks/profiles/<stage>/` and the dashboard legend.
- `plot_dashboard.py` reads `pareto_c<C>.json`, `context_l<L>.json` (L parsed from filename), `nsys_metrics.json`,
  `ncu_metrics.json`, using `vllm bench serve` keys (`output_throughput`, `p{50,90,99}_itl_ms`, `mean_tpot_ms`,
  `mean_ttft_ms`). Changing filenames or percentiles in bench scripts breaks plots. Run it from repo root (relative paths).
- Any engine must serve OpenAI-compatible streaming `POST /v1/chat/completions` on `server.port`, accept
  `model.name`, honour `ignore_eos`, and send a final `usage` chunk — required by `vllm bench serve` and the UI.

## Profiling gotchas
- `profile_nsys.sh` drives the session opened by `NSYS=ON serve.sh` (`nsys launch`) and picks up `report*.nsys-rep`
  from the **repo root** (serve scripts `cd` there). Phase timings use NVTX ranges when present, falling back to
  a GPU kernel timeline split (`phase_measurement_source` in the JSON).
- `profile_ncu.sh` is vLLM-internal (own `vllm.LLM`, hooks layer 0 via `llm_engine.model_executor…`,
  `VLLM_ENABLE_V1_MULTIPROCESSING=0`). Stop the server first. Custom stages need their own runner emitting the same schema.
- Roofline ceilings come from the first plotted stage's `ncu_metrics.json`; tensor FLOPs are an estimate (inst × 4096).

## Misc
- Server binds `0.0.0.0`; clients rewrite it to `127.0.0.1`. `max_model_len 9216` = 8192 sweep + 64 out + template.
- Open-loop script filename has parentheses: `./benchmarks/bench_open_loop\(temporary\).sh`.
- Stage dirs must sit exactly two levels below root (`serve.sh` resolves `REPO_ROOT` as `../..`).
